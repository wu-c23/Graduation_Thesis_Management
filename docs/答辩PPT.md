## 第 1 页：封面

**标题**：毕业论文（设计）过程管理平台

**副标题**：把毕业设计的每一步都留在系统里

**信息**：姓名 / 学号 / 班级 / 指导教师 / 2026 年 11 月

**讲解**：

> 各位老师好，我汇报的项目是毕业论文过程管理平台，主要解决毕业设计过程中进度不透明、材料分散和审核标准不统一的问题。

---

## 第 2 页：问题与目标

**左侧：三个痛点**

- 学生不清楚当前进度和下一步任务；
- 材料通过聊天工具传递，版本与退回原因难追溯；
- 导师需要逐个询问学生，缺少全局视图。

**右侧：三个目标**

- 过程可追踪：六步固定流程；
- 材料可审核：版本保留、意见可回看；
- 进度可汇总：一屏看到所有学生。

**讲解**：

> 项目不追求覆盖全部教务功能，只聚焦过程管理。范围在第 1 周冻结，后续只修缺陷、补文档。

---

## 第 3 页：六步流程

**流程条**：

```text
需求文档 → 原型 → 设计评审 → 周报 → 代码仓库 → 测试报告
```

**分工**：

| 学生 | 导师 |
|---|---|
| 提交材料、周报、仓库、测试报告 | 审核、评审、批阅、退回 |

**规则**：

- 每步有明确完成条件；
- 退回后可修改重交；
- 进度按“连续完成前缀”计算。

**讲解**：

> 六步不是六个孤立页面，而是一条有前后依赖的链路。比如设计评审必须在需求和原型都通过后进行。

## 第 4 页：技术架构

**架构图文字版**：

```text
Vue 3 + Element Plus
        │ JWT / JSON
Spring Boot 3 + MyBatis-Plus
        ├── H2（开发）/ MySQL（脚本预留）
        ├── 本地文件存储 uploads/
        └── GitHub / Gitee 公开 API
```

**技术选型**：

- 前端：Vue 3、Vite、Element Plus、Axios；
- 后端：Java 21、Spring Boot 3.3.5；
- 鉴权：JWT HS256 + 拦截器；
- 数据：6 张表，18 个接口。

**讲解**：

> 选择这套技术栈的原因是课程时间内可掌握、启动成本低。H2 让系统不依赖外部数据库，一条命令即可运行。

## 第 5 页：数据模型与进度计算

**6 张表**：

`sys_user`、`project`、`artifact`、`design_review`、`weekly_report`、`repo_binding`

**设计要点**：

- 材料追加版本，不覆盖历史；
- 周报按“课题 + 周次”唯一；
- 评审按轮次保留；
- **不建阶段完成表**。

**进度来源**：

| 步骤 | 数据来源 |
|---|---|
| 需求 / 原型 | 最新材料是否通过 |
| 设计评审 | 前置材料 + 最新评审结论 |
| 周报 | 是否有已批阅周报 |
| 仓库 | 是否绑定且同步成功 |
| 测试报告 | 最新报告是否通过 |

**讲解**：

> 这是项目的核心设计：进度不单独存储，而是从业务数据实时推导。这样总览、详情和学生端天然一致，也不会出现进度表与材料状态矛盾。

## 第 6 页：学生端

**页面结构**：

- 顶部六步进度；
- 材料提交 / 设计评审 / 周报 / 代码仓库 / 测试报告五个 Tab。

**关键能力**：

- 文件或外链二选一；
- 历史版本、导师评语、评分、鉴权下载；
- 退回后原地重交；
- 仓库自动同步失败时可手工填写。

**截图**：`docs/screenshots/week6-student-complete.png`

**讲解**：

> 学生端最重要的不是表单数量，而是让学生清楚“我现在在哪一步、下一步做什么、上次为什么被退回”。

## 第 7 页：导师总览

**四张卡片**：学生数、待审核材料、待批阅周报、平均完成率

**表格**：六步圆点矩阵、当前阶段、待办数、最近动态

**交互**：关键词搜索、状态筛选、进度/待办排序

**详情抽屉**：材料审核、设计评审、周报批阅、仓库信息

**截图**：`docs/screenshots/week5-advisor-overview.png`

**讲解**：

> 总览的统计由后端批量聚合，避免 N+1；每名学生的六步状态复用同一进度服务。导师可以一屏判断先处理谁。

## 第 8 页：安全与异常处理

**安全**：

- BCrypt 存储密码；
- JWT 鉴权，角色路径隔离；
- Service 层校验课题归属；
- 上传白名单 + 20MB + UUID 文件名；
- 下载鉴权与路径校验；
- 仓库 API 主机白名单，降低 SSRF 风险。

**异常路径**：

| 异常 | 处理 |
|---|---|
| 重复提交 | 400 + 明确提示 |
| 退回未填评语 | 前端必填 + 后端校验 |
| Token 过期 | 401，前端回登录页 |
| 仓库同步失败 | FAILED 状态 + 手工兜底 |
| 统计越界 | 400 |

**讲解**：

> 安全上至少保证“不越权、不信任前端、不暴露存储路径”。异常路径都给出可继续操作的出口，而不是直接报 500。
