# 用户手册

> 系统名称：毕业论文（设计）过程管理平台
> 版本：v1.0（第 5 周末功能冻结）
> 适用对象：学生、指导教师
> 运行方式：本地浏览器访问 <http://localhost:5173>（启动方法见 `docs/运行说明.md`）

---

## 1. 系统能做什么

系统把毕业设计过程固定为六步，学生按步骤提交，导师逐项审核：

**需求文档 → 原型 → 设计评审 → 周报 → 代码仓库 → 测试报告**

- 学生端：查看六步进度、提交材料、提交周报、绑定代码仓库、提交测试报告；
- 导师端：一屏查看名下所有学生进度与待办，审核材料、评审设计、批阅周报、查看仓库信息；
- 所有进度由真实业务数据计算，不提供手工修改进度的入口。

|---|---|---|---|

## 2. 登录

1. 打开 <http://localhost:5173>，进入登录页；
2. 输入学号 / 工号与密码；
3. 点击“登录”。

登录成功后：

- 学生进入“我的课题”工作台；
- 导师进入“学生总览”。

登录页顶部显示后端与数据库连接状态。若显示“后端未连接”，先确认后端已在 8080 端口启动。

Token 有效期 8 小时。过期或失效时，页面自动清除本地会话并跳回登录页，重新登录即可。

---

## 3. 学生操作说明

登录后页面分为上下两部分：顶部是六步进度，下面按 Tab 分为“材料提交”“设计评审”“周报”“代码仓库”“测试报告”。

### 3.1 查看六步进度

每个步骤显示三种信息：

| 显示 | 含义 |
|---|---|
| 已通过 / 已完成 | 该步骤对应的业务条件已满足 |
| 审核中 / 进行中 | 已提交，等待导师处理 |
| 已退回 | 导师退回，需要按意见修改后重交 |
| 未开始 | 尚未提交或尚未满足条件 |

进度按“连续完成”计算：如果第 2 步被退回，后面的步骤即使已有数据，也不会计入完成数。

### 3.2 材料提交

适用材料：需求文档、原型、测试报告。

1. 在汇总表找到对应材料行，点击“提交”或“重新提交”；
2. 选择提交方式（二选一）：
   - **上传文件**：支持 PDF、DOCX、ZIP、PNG、JPG，单个文件不超过 20MB；
   - **填写外链**：仅支持 `http` / `https` 地址，例如 Figma、Axure、在线文档；
3. 测试报告需额外填写用例数、通过率（0–100）、缺陷数，均为可选；
4. 点击“提交”。

规则：

- 同一类型材料处于“待审核”时不能重复提交；
- 每次提交都会生成新版本，旧版本、导师评语和评分保留在“提交历史”；
- 已通过的材料仍可重新提交，但该步骤会回到“审核中”，后续步骤暂停计入完成；
- 文件材料可在历史表点击“下载”，外链材料直接点击链接打开。

### 3.3 设计评审

- 需求文档和原型**都通过**后，导师才能进行设计评审；
- 学生在本 Tab 查看评审轮次、结论、评分、评语、评审人和时间；
- 评审不通过时，按评语修改材料后重新提交，等待下一轮评审。

### 3.4 周报

1. 点击“提交周报”；
2. 选择周次（1–30），填写本周进展（不超过 2000 字）；
3. 提交后状态为“待批阅”。

规则：

- 同一课题同一周只保留一条周报；
- 待批阅或已批阅状态下不能重复提交；
- 导师退回后，可修改内容后原地重交，不新增重复周次；
- 导师批阅意见会显示在周报列表中；
- 至少 1 篇周报被批阅后，第 4 步完成；之后新增周报不会让已完成状态回退。

### 3.5 代码仓库

1. 输入公开仓库地址，例如 `https://github.com/owner/repo` 或 `https://gitee.com/owner/repo`；
2. 点击“绑定并同步”；
3. 同步成功后显示平台、提交数、最近提交时间和最近同步时间。

说明：

- 只支持公开的 GitHub / Gitee 仓库，地址会自动去除 `.git` 与末尾斜杠；
- 自动同步连接超时 3 秒、请求超时 5 秒；
- 同步失败时状态显示“失败”，可点击“重新同步”；
- 仍然失败时，使用“手工填写”录入提交总数与最近提交时间，手工数据同样视为同步成功，可继续演示；
- 绑定成功且同步成功后，第 5 步完成。

### 3.6 测试报告

1. 在“材料提交”Tab 找到测试报告行并提交文件或外链；
2. 填写用例数、通过率、缺陷数（可选，但填写后会随材料一起展示给导师）；
3. 导师审核通过后，第 6 步完成；
4. 被退回时按评语修改并重新提交，历史版本保留。

## 4. 导师操作说明

### 4.1 学生总览

顶部四张统计卡片：

| 卡片 | 含义 |
|---|---|
| 名下学生 | 学生总数，并显示已完成六步的人数 |
| 待审核材料 | 待处理材料数量 |
| 待批阅周报 | 待处理周报数量 |
| 平均完成率 | 所有学生已完成步数 /（学生数 × 6） |

学生表格包含：学生、学号、课题、六步进度圆点、当前阶段、待处理数量、最近动态、操作。

- 圆点颜色对应各步骤状态，鼠标悬停显示“步骤名：状态”；
- 最近动态取材料提交、周报提交、设计评审、仓库同步中的最新时间；
- 工具栏支持关键词搜索、状态筛选（全部 / 有待办 / 进行中 / 已完成六步）和排序（默认 / 进度从高到低 / 待办从多到少）。

### 4.2 查看与审核材料

1. 点击学生行的“查看详情”，打开详情抽屉；
2. 在“材料审核”区查看提交内容、类型、时间、测试统计和附件；
3. 对待审核材料选择“通过”或“退回”；
4. 可填写 0–100 评分；退回时**必须填写评语**；
5. 确认后学生端立即看到结果。

退回后，学生需要重新提交；新版本会出现在历史中，不会覆盖旧版本。

### 4.3 设计评审

- 需求与原型全部通过后，评审表单才可用；
- 填写 0–100 分、结论（通过 / 退回）和评语；
- 每轮评审保留历史，轮次自动递增；
- 通过后学生端前 3 步完成。

### 4.4 批阅周报

1. 在详情抽屉的“周报批阅”区找到待批阅周报；
2. 点击“批阅”或“退回”；
3. 填写批阅意见；退回时意见必填；
4. 批阅后学生端第 4 步完成，总览待办数量同步减少。

### 4.5 查看代码仓库

详情抽屉展示仓库地址、平台、提交数、同步状态、最近提交时间和最近同步时间。导师只读，不提供修改入口。

## 5. 状态说明

| 状态 | 出现位置 | 含义 |
|---|---|---|
| `待审核` | 材料 | 已提交，等待导师处理 |
| `已通过` | 材料 | 导师通过，对应步骤完成 |
| `已退回` | 材料 | 导师退回，需按评语修改后重交 |
| `待批阅` | 周报 | 已提交，等待导师批阅 |
| `已批阅` | 周报 | 导师批阅完成 |
| `同步成功` | 仓库 | 自动或手工同步成功 |
| `同步失败` | 仓库 | 自动同步失败，可重试或手工填写 |
| `未开始 / 审核中 / 进行中 / 已退回 / 已通过` | 六步进度 | 步骤当前状态 |

## 6. 常见问题

**Q1：提示“该材料正在等待导师审核，请勿重复提交”？**
同一类型材料已有待审核记录，等待导师处理即可。被退回后可以重新提交。

**Q2：为什么重新提交已通过的材料后，进度反而下降了？**
进度按连续完成前缀计算。重新提交会让该步骤回到“审核中”，后续步骤暂不计入，重新通过后恢复。

**Q3：仓库同步失败怎么办？**
先确认仓库是公开的、地址格式正确；点击“重新同步”。仍失败时使用“手工填写”，录入提交总数和最近提交时间。

**Q4：为什么提交数不准确？**
提交总数取自 GitHub / Gitee 公开 API 的分页头，平台限流或格式变化时可能不准确。可按页面提示手工填写。

**Q5：上传失败？**
检查扩展名是否在白名单内（PDF/DOCX/ZIP/PNG/JPG）、文件是否超过 20MB、是否同时选择了文件和填写了外链（只能二选一）。

**Q6：导师看不到我的数据？**
确认登录的是 `tea001`，且该学生确实在名下。不同导师之间的数据完全隔离。

**Q7：页面提示 401 / 自动跳回登录页？**
Token 已过期或失效，重新登录即可。

**Q8：同一周的周报能改吗？**
待批阅或已批阅状态不能直接改；被退回后可修改重交。系统只保留最近一次内容。

## 7. 演示建议

一次完整演示可以按以下顺序进行（约 5 分钟，详细脚本见 `docs/演示脚本.md`）：

1. 导师登录，展示总览、完成率、待办与六步矩阵；
2. 学生登录，展示六步进度与材料历史；
3. 学生提交需求 → 导师退回 → 学生重交 → 导师通过；
4. 导师完成设计评审；
5. 学生提交周报 → 导师批阅；
6. 学生绑定仓库并手工兜底；
7. 学生提交测试报告 → 导师通过 → 六步完成；
8. 回到导师总览，完成率与待办同步更新。
