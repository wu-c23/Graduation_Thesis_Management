## 三、实验内容与过程

### 3.1 需求分析与范围冻结

根据课程每周约 6 学时的实际投入，确定系统只保留一条可演示的主线，角色固定为学生和导师：

- 学生：提交需求文档、原型、测试报告，提交周报，绑定代码仓库，查看反馈。
- 导师：查看名下学生，审核材料，完成设计评审，批阅周报，审核测试报告。
- 管理员：不开发管理界面，仅通过种子 SQL 初始化账号和项目。

六步固定流程：

```text
需求文档 → 原型 → 设计评审 → 周报 → 代码仓库关联 → 测试报告
```

明确不做选题双选、动态阶段模板、站内通知、统计图表、多轮评审、文件版本表、OAuth、自动定时同步、移动端、自动化 E2E 和性能测试，避免范围膨胀。

形成功能需求 FR-01 至 FR-11、状态流转规则、验收标准和追踪矩阵，输出《需求规格说明书 v0.1》。

### 3.2 低保真原型设计

使用原生 HTML/CSS 绘制 8 个静态页面，覆盖第 1 周五步验收所需的全部主要画面：

1. 登录页；
2. 学生工作台（六步进度 + 5 个功能 Tab）；
3. 材料提交 / 查看反馈；
4. 设计评审；
5. 周报；
6. 代码仓库关联；
7. 测试报告；
8. 导师学生列表。

原型入口为 `prototype/index.html`，页面之间可点击跳转，但不提交真实数据。原型重点表达区域划分、按钮位置、状态标签和异常提示，不做高保真视觉设计。

### 3.3 数据库与接口设计

设计 6 张表，覆盖用户、项目、材料、设计评审、周报和仓库绑定：

| 表名 | 作用 | 关键字段 |
|---|---|---|
| `sys_user` | 用户与角色 | `username`、`password_hash`、`role` |
| `project` | 学生课题与导师关系 | `student_id`、`advisor_id`、`title` |
| `artifact` | 需求 / 原型 / 测试报告材料 | `type`、`status`、`score`、`feedback` |
| `design_review` | 设计评审记录 | `score`、`comment`、`result` |
| `weekly_report` | 周报 | `week_no`、`content`、`status`、`comment` |
| `repo_binding` | 代码仓库绑定 | `repo_url`、`commit_count`、`sync_status` |

关键约定：

- 材料状态：`SUBMITTED` / `APPROVED` / `RETURNED`；重新提交插入新记录，旧记录只读，天然形成历史。
- 评审结论：`PASS` / `RETURN`。
- 周报状态：`SUBMITTED` / `REVIEWED` / `RETURNED`。
- 仓库同步状态：`SUCCESS` / `FAILED` / `NOT_SYNCED`。
- 不单独建立阶段表，六步进度由上述数据实时计算。

同时设计约 16 个 REST 接口，统一返回 `{ code, message, data }`，并绘制 Mermaid ER 图，输出《概要设计 v0.1》。

### 3.4 后端脚手架

搭建 Spring Boot 工程，完成以下基础设施：

- 统一响应体 `ApiResponse<T>` 和全局异常处理；
- CORS 配置，允许本地 Vite 开发服务器访问 `/api/**`；
- H2 文件数据库，启用 MySQL 兼容模式；
- `schema.sql` 创建 6 张表，`data.sql` 使用 `MERGE INTO ... KEY(id)` 幂等写入 3 个账号和 2 个项目；
- 使用 BCrypt 保存演示账号密码，种子密码为 `123456`；
- 实现 `GET /api/health`，同时检查 Web 服务、MyBatis-Plus 与数据库，并返回用户数量；
- 编写 MockMvc 集成测试，使用内存 H2 验证健康检查结果。

### 3.5 前端脚手架

搭建 Vue 3 + Vite 工程，完成以下内容：

- 配置 `/api` 代理到 `http://localhost:8080`；
- Axios 统一实例和响应拦截器；
- Vue Router 配置 `/login`、`/student`、`/advisor` 路由；
- 登录页骨架，可显示演示账号并实时请求后端健康检查；
- 学生工作台骨架：六步进度条、5 个 Tab、静态表格和“第 2–4 周接入”提示；
- 导师首页骨架：统计卡片、名下学生、当前阶段和待处理数量占位。

第 1 周不实现真实登录，登录按钮仅提示 JWT 登录将在第 2 周接入，避免在脚手架上重复返工。

## 五、遇到的问题与解决方法

### 问题 1：开发机没有 MySQL 和 Docker

**现象**：计划使用 MySQL 8.0，但本机未安装 MySQL 客户端/服务，也未安装 Docker，无法按原计划启动数据库。

**解决**：第 1 周改用 H2 文件数据库并以 MySQL 兼容模式运行，连接串为：

```text
jdbc:h2:file:./data/thesisdb;MODE=MySQL;DATABASE_TO_LOWER=TRUE;AUTO_SERVER=TRUE
```

同时保留 `db/schema-mysql.sql` 和 `db/data-mysql.sql`，供后续安装 MySQL 时切换。当前实现的 SQL 只使用通用语法，未依赖 MySQL 专有函数，切换成本较低。

**影响**：开发阶段无阻塞；MySQL 脚本尚未在真实 MySQL 实例中验证，若课程要求必须使用 MySQL，需要补装环境并做一次切换验证。

### 问题 2：`mvn spring-boot:run` 在中文路径下启动失败

**现象**：执行 `mvn spring-boot:run` 报错：

```text
错误: 找不到或无法加载主类 com.example.thesis.ThesisApplication
原因: java.lang.ClassNotFoundException: com.example.thesis.ThesisApplication
```

**排查**：

- `target/classes/com/example/thesis/ThesisApplication.class` 已正常生成；
- `mvn test` 可以正常加载应用上下文，说明代码和类路径声明正确；
- 在 `pom.xml` 中显式配置 `<mainClass>` 后仍然失败；
- 使用 `java -jar` 运行打包后的 JAR 可以正常启动。

**结论**：问题出在当前包含中文的工程路径与 Maven 插件运行时类路径处理，而非业务代码。

**解决**：采用已验证的启动方式：

```bash
cd backend
mvn -q -DskipTests package
java -jar target/thesis-platform-0.1.0.jar
```

并新增 `start-backend.bat`、`start-frontend.bat` 和 `start-all.bat` 简化启动；使用 IDEA 时也可直接运行 `ThesisApplication`。README 已同步这一说明。

### 问题 3：种子数据重复执行会产生重复记录

**现象**：Spring Boot 每次启动都会执行 `data.sql`，普通 `INSERT` 会导致主键冲突或重复数据。

**解决**：H2 脚本使用 `MERGE INTO ... KEY(id)`，MySQL 脚本使用 `INSERT ... ON DUPLICATE KEY UPDATE`，保证多次启动后数据仍然幂等。

### 问题 4：后端首次启动较慢导致健康检查过早失败

**现象**：打包后首次启动约需 16 秒，启动后立即请求健康检查会连接失败。

**解决**：确认日志出现 `Started ThesisApplication` 后再访问；验证脚本中加入等待。该现象属于启动时序问题，不是接口故障。

### 问题 5：前端构建出现大文件块警告

**现象**：`npm run build` 提示部分 chunk 超过 500 kB。

**分析**：当前全量引入 Element Plus，且未做路由懒加载与分包。

**处理**：构建成功，不影响第 1 周验收；该项属于性能优化，暂不处理，后续如时间允许再做按需引入。

## 六、实验总结

本实验的核心不是堆功能，而是在课程学时约束下做出可交付、可演示的范围决策。第 1 周通过固定角色、固定六步流程、固定页面和 6 张表，把系统范围控制在可实现的 MVP 内，并用 18.2% 的交付量完成了“需求—原型—设计—骨架”的基线。

通过本周工作，确认了以下事实：

1. 前后端工程均能在当前 Windows 环境构建和运行；
2. H2 可以在没有 MySQL 的情况下承担开发数据库角色；
3. 中文路径会影响 Maven 插件启动，但不影响打包运行，已经有稳定的替代启动方式；
4. 第 1 周的范围冻结有效，第 2 周可以直接进入登录和真实页面开发，不需要返工原型或表结构。
