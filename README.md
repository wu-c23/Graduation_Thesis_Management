## 3. 快速启动

### 3.1 启动后端

Windows 推荐直接双击根目录的 `start-backend.bat`，它会自动打包并启动。

命令行手动启动：

```bash
cd backend
mvn -q -DskipTests package
java -jar target/thesis-platform-0.1.0.jar
```

> 本项目路径包含中文。已验证 `java -jar` 可正常运行；`mvn spring-boot:run` 在该路径下可能因 Maven 插件类路径编码问题报 `ClassNotFoundException`，因此不作为推荐命令。使用 IDEA 时可直接运行 `ThesisApplication`。

访问健康检查：

```bash
curl http://localhost:8080/api/health
```

预期返回 `code = 0`、`database = UP`、`userCount = 3`。

H2 控制台（仅开发环境）：

- 地址：<http://localhost:8080/h2-console>
- JDBC URL：`jdbc:h2:file:./data/thesisdb;MODE=MySQL;DATABASE_TO_LOWER=TRUE;AUTO_SERVER=TRUE`
- 用户名：`sa`
- 密码：留空

### 3.2 启动前端

Windows 推荐直接双击根目录的 `start-frontend.bat`。

命令行手动启动：

```bash
cd frontend
npm install
npm run dev
```

访问 <http://localhost:5173>。

登录页会自动请求 `/api/health`，显示后端与数据库连接状态。

也可以双击 `start-all.bat`，同时打开后端和前端两个命令行窗口。

### 3.3 查看低保真原型

直接双击打开：

```text
prototype/index.html
```

无需启动服务。原型包含 8 个静态页面，按钮不提交真实数据。

## 7. 常见问题

**Q：后端启动报数据库被占用？**
H2 文件库同一时间只能被一个进程打开。关闭其他后端进程后重试；测试使用内存库，不受影响。

**Q：前端健康检查显示“后端未连接”？**
确认后端已在 8080 端口启动；前端开发服务器通过 Vite 代理访问 `/api`。

**Q：为什么不用 MySQL？**
当前开发机未安装 MySQL，第 1 周用 H2 降低启动成本。`db/schema-mysql.sql` 和 `db/data-mysql.sql` 可直接用于 MySQL 8.0。

**Q：为什么学生访问导师接口返回 403？**
系统按角色和路径隔离权限：`/api/student/**` 仅学生可访问，`/api/advisor/**` 仅导师可访问。即使持有合法 Token，角色不匹配也会返回 403。

**Q：JWT 密钥如何配置？**
开发环境在 `application.yml` 中提供默认密钥；部署时请设置环境变量 `JWT_SECRET` 覆盖，密钥至少 32 字节。Token 有效期默认 8 小时。

**Q：登录过期或 Token 失效会怎样？**
后端返回 401，前端清除本地会话并跳转登录页；重新登录即可。

**Q：上传的文件保存在哪里？**
默认保存在项目根目录的 `uploads/{projectId}/`，文件名使用 UUID，原始文件名保存在数据库中。可通过环境变量 `UPLOAD_DIR` 修改根目录。单文件上限 20MB，支持 PDF、DOCX、ZIP、PNG、JPG。

**Q：为什么不能下载外部链接材料？**
外部链接材料没有本地文件，页面上直接点击链接即可打开（如 Figma、Axure、在线文档）；下载按钮只对文件材料显示。

**Q：退回后重新提交会覆盖旧材料吗？**
不会。每次提交都插入新记录，旧版本、导师评语和评分都会保留；六步进度以最新一条记录为准。

**Q：为什么重新提交已通过的材料后，后续步骤变成未完成？**
进度按“连续完成的前缀”计算。需求或原型重新提交后，该步骤回到审核中，后续步骤不能继续算作当前完成；历史设计评审记录仍保留，待材料重新通过后可再次评审。

**Q：代码仓库同步失败怎么办？**
先确认仓库是公开的，且地址为 `https://github.com/owner/repo` 或 `https://gitee.com/owner/repo`。失败时页面会显示“同步失败”并提示公开 API 不可用的可能原因，可点击“重新同步”重试；仍失败时使用“手工填写”，录入提交总数与最近提交时间即可继续演示，手工数据同样视为同步成功。

**Q：为什么同步得到的提交数不准确？**
提交总数取自平台公开 API 的分页头（GitHub `Link`、Gitee `X-Total-Count` 或 `Link`）。平台限流或分页格式变化时可能只返回 1，此时按页面提示使用手工填写。系统只统计默认分支的提交，不拉取提交列表。

**Q：同一周的周报可以提交多次吗？**
待批阅或已批阅状态下不能重复提交。被导师退回后，修改内容会覆盖原记录并重新进入待批阅，不保留中间修订历史；如需保留完整过程，可在内容中自行记录修订说明。

**Q：测试报告的通过率和用例数必填吗？**
不是必填，但只允许在测试报告类型填写。用例数与缺陷数不能为负，通过率必须在 0–100 之间；导师审核时会同时看到这三项统计。
